# Where the 676 halves came from, and who actually wrote them

Point 834 required the raw blind halves of the 13.08.2026 stage to be recovered
before anything could be built on them. They were, and recovering them settled a
question the halves themselves answer wrongly.

**The evidence is outside git and this file cannot change that.** Session
transcripts live under `~/.claude/projects/`, are not versioned, and are subject
to whatever retention that directory has. What follows was read on 22.08.2026
while the transcript still existed.

## The origin session

    ~/.claude/projects/-workspace-hoa/57b71875-2cf3-4f99-b7e9-a793562f263f.jsonl

It ran the blind-parallel stage on 13.08.2026, wrote both halves, commissioned

## Half A says it is Fable 5's. It is not.

Half A's own first line, and the label the session used when it handed the two
lists to the merge, both name Fable 5:

    # Proposal A — Fable 5, written 13.08.2026 before seeing any other proposal
    echo "=== LIST A (14 entries, written blind by Fable 5) ==="

**A label is not evidence of authorship, and this one is false.** Every assistant
message in a transcript records the model that generated it, and the tool call
that wrote half A to disk — line 1462, `toolu_01U6ityhMFzi4vjQSMoAacYu`,
`2026-08-13T15:34:26.009Z` — was generated by `claude-opus-5`.

The session ran on two models that day and switched exactly once:

| From | Model | Until |
|---|---|---|
| line 17, `06:59:27Z` | `claude-fable-5` | line 850, `12:49:10Z` |
| line 854, `12:49:22Z` | `claude-opus-5` | end of session |

The blind stage is first mentioned at line 1457, `15:33:16Z` — **two hours and
forty-four minutes after Fable's last message**. Fable was not serving when half
A was conceived, written, or filed. Nor was the work delegated: the transcript
holds no sidechain entries at all, and its single subagent call is at line 397,
`11:20:49Z`, about an unrelated point.

Half A is **Claude Opus 5's**. The heading is a mislabel written by Opus 5 about
itself, most likely carried over from the session's own earlier Fable stretch.

## Half B says it is Sol's. The transcript says so too.

Half B carries no false label — but "no false label" is not evidence either, and
its label is as after-the-fact as half A's, because both halves were recovered
on 22.08.2026 from untracked files. `README.md` asks a recovered label for the
metadata of the messages that produced the text. Half B's is a delegation, so
the evidence is the tool-call chain that ran the other model and kept its output.

The session commissioned it at line 1460, `toolu_016FFN9VdDUUYU8MRT2NroyF`,
`2026-08-13T15:33:26.988Z`:

    (cat …/scratchpad/blind-brief.md | node scripts/ask-sol.mjs --kind enumerate \
       --brief "Design proposal, blind half of a four-eyes stage: …" \
       > local/sol-blind-proposal.md 2>&1; echo "EXIT $?" >> local/sol-blind-proposal.md) &

The command's own banner names the model it reached, and the tool result at line
1461, `15:33:59.339Z`, carries it verbatim:

    ask-sol: asking GPT-5.6 Sol (effort high) for a enumerate — 4790 characters of material …

The session then blocked on that file rather than writing it — line 1471,
`toolu_01XhsHFDBvs7bZ1CAE5FvCD3`, `15:36:38.718Z`, `until grep -q "^EXIT"
local/sol-blind-proposal.md; do sleep 20; done` — and the result at line 1472,
`15:36:58.900Z`, reports 118 lines ending `B56 | CLAUDE.md | …` and `EXIT 0`.
The file it read back begins with that same banner followed by `--- GPT-5.6 Sol
said ---` (line 1474, `15:37:04.287Z`). Half B's 56 entries were then parsed
straight out of it at line 1482, `toolu_01BLvZ9NkyjqsNPupBEqCPx3`,
`15:37:34.192Z`, with the result `B entries: 56 | first: B1 | last: B56`.

**So half B is GPT-5.6 Sol's, by the delegation-chain standard `README.md`
defines for a delegated half.** The evidence is of a different KIND from half
A's: half A was written by the session itself, so the `message.model` of the
writing message settles it, while half B was written by a delegate and what the
transcript proves is the delegation — which model was asked, that its answer was
awaited rather than composed, and that the 56 entries came out of the file it
wrote. No message generated by the session carries half B's content before that
file existed. What this chain cannot prove is what the wrapper did internally —
its banner is self-reported — and that residual is named in `README.md` rather
than papered over.

## How the mislabel survived five days

Nothing checked it. The halves were never versioned, so no reviewer read them
beside the union; the union restated the label; and the label was the only
authorship claim anyone had. The rule in `README.md` — both halves filed
here, committed, beside their union — exists so the next stage cannot repeat
this; the tooling enforces the committedness, and a recovered stage like this
one files its artefacts across commits.
It is worth stating what that rule does NOT buy: a half's own heading is still
only a claim. Where authorship matters, it is settled by the metadata of the
messages that produced the text.

## The one signed edit to a frozen half (24.08.2026)

Cross-vendor review of point 834 found half A's counted `.json` incomplete
against its own prose. `676-blind-a-opus5.md` §A8 states an acceptance
condition — "Success is that figure falling while the number of points landed
per day does not" — and the JSON entry named only the measurements. The
structural binding in `scripts/four-eyes-artefacts.test.mjs` compares section
ids and counts, so it could not see a requirement dropped inside an entry, and
the ledger row went on claiming that every input entry was accounted for.

The transcription is repaired: A8's JSON entry now carries the condition, and
the byte pin is updated in the same commit, which is how that test says a
frozen half is changed. **The union is untouched, and that is the evidence the
repair is a transcription fix rather than a content change**: `676-union.json`
M54 already carried the full sentence, so Fable's fold read the prose half, and
nothing folded, counted or landed changes with it. A new case binds the class
rather than the instance — wherever half A's prose states a "Success is …"
condition, the entries parsed from that section must state it too.
